## Engineering Philosophy

Most systems fail not because of complex bugs, but because of poor observability, unclear ownership, and APIs that were never designed to be wrong.

A few things I treat as non-negotiable:

**Reliability over features.** `p99` latency matters more than the tenth feature flag. A system that degrades gracefully under load is worth more than one that works perfectly with no traffic.

**Observability is a first-class concern.** Every service I build ships with structured logs, Prometheus metrics, and distributed traces. If you cannot tell what a system is doing from the outside, it is not production-ready.

**Simple APIs are hard to write.** Clean interfaces require more upfront thought, not less. I'd rather spend a week getting an API contract right than a month explaining why it's confusing.

**Documentation is code.** An undocumented system is a system only one person understands. I write runbooks, ADRs, and inline comments the same way I write tests — as a first-class engineering deliverable.

**Maintainability is a team property.** Code that only the author understands is a liability. I default to explicit over clever, and to verbose over terse.

## Featured Projects

### [OpenFlow](https://github.com/mihir-dixit2k27/openflow) — Distributed Workflow Automation Platform

> Production-grade DAG execution engine built in Go, designed for high-throughput workflow orchestration.

**Architecture**

```
                ┌─────────────┐
                │  REST API   │  Gin · OpenTelemetry
                │  (Gin/HTTP) │
                └──────┬──────┘
                       │
              ┌────────▼────────┐
              │  Workflow Engine │  DAG parser · optimistic lock
              │  Scheduler       │  RBAC · retry policies
              └───┬─────────┬───┘
                  │         │
         ┌────────▼─┐   ┌───▼────────┐
         │ Worker   │   │  Dead       │
         │ Pool     │   │  Letter     │
         │ (gRPC)   │   │  Queue      │
         └────┬─────┘   └─────────────┘
              │
   ┌──────────▼──────────┐
   │  NATS JetStream      │  Durable streams · consumer groups
   └──────────┬───────────┘
              │
   ┌──────────▼──────────┐
   │  PostgreSQL           │  Optimistic locking · connection pool
   └─────────────────────┘
```

**Stack:** `Go` `Gin` `gRPC` `PostgreSQL` `Redis` `NATS JetStream` `Prometheus` `OpenTelemetry` `Docker` `GitHub Actions`

**Key Design Decisions**

- DAG execution with cycle detection and topological ordering
- Worker pool with configurable concurrency and context-aware cancellation
- Distributed retries with exponential backoff and jitter
- Dead Letter Queue for failed workflow inspection and replay
- Optimistic locking via `version` column — no advisory locks, no serialization failures under normal load
- RBAC with policy enforcement at the handler layer, not the database layer

**Metrics**

| Metric | Value |
|--------|-------|
| Throughput | 50,000 workflows/day |
| p95 API latency | < 50 ms |
| Retry success rate | > 92% on transient failures |

### [Hotreload](https://github.com/mihir-dixit2k27/hotreload) — Production Go CLI

> Live-reload CLI for Go development with crash loop detection and production-grade signal handling.

**Stack:** `Go` `Prometheus` `GitHub Actions` `GoReleaser`

**Key Design Decisions**

- Context-based cancellation propagated through the entire process tree — no orphan goroutines
- Crash loop detection with configurable threshold and backoff — prevents runaway restart loops
- Prometheus metrics endpoint exposed for integration into existing monitoring pipelines
